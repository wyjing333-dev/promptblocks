# Prompt运行评分模块 - 设计规划文档

## 一、现状分析

### 已有基础
- `prompt-scorer.html`：独立页面，5维度评分（清晰度/完整性/可执行性/简洁度/具体性）
- 评分方式：纯前端文本匹配（检查动词、长度、标点等）
- 输出：总分0-100 + 各维度分数 + 改进建议 + 推荐积木

### 现有问题
1. 评分太粗糙——只检查"有没有"某个词，不评估"质量如何"
2. 无AI调用——纯规则匹配，无法理解语义
3. 未集成到主页面——用户需要跳到单独页面使用
4. 无历史记录——评分完就没了，无法对比优化前后
5. 无A/B对比——无法对比两个Prompt版本的得分变化

## 二、升级目标

### 核心目标
将评分模块从"规则匹配器"升级为"AI驱动的Prompt质量评估器"，集成到主页面，支持运行时评分和优化建议。

### 参考方法论
基于 promptfoo-evals 技能的评估框架：
- 定义评估维度（dimensions）和评分标准（rubric）
- 设计assertion断言（每个维度用明确的通过/失败条件）
- 支持多模型对比评分（同一Prompt在ChatGPT/Claude/阶跃上的表现差异）
- 输出结构化评估报告

## 三、架构设计

### 3.1 评分维度（6维度，每维度0-100）

| 维度 | 权重 | 说明 | 检测方式 |
|------|------|------|----------|
| 清晰度 Clarity | 20% | Prompt是否表达清晰、无歧义 | AI语义评估 + 规则辅助 |
| 完整性 Completeness | 20% | 是否包含角色/任务/上下文/约束/格式 | 积木覆盖检测 + AI评估 |
| 可执行性 Actionability | 20% | AI能否据此产出合格结果 | AI评估（模拟执行） |
| 简洁度 Conciseness | 15% | 是否冗余、有无废话 | 字数/重复率 + AI评估 |
| 具体性 Specificity | 15% | 是否足够具体、有量化指标 | 关键词密度 + AI评估 |
| 安全性 Safety | 10% | 是否有越狱风险、敏感内容 | 规则检测 + AI评估 |

### 3.2 评分等级

| 等级 | 分数范围 | 含义 |
|------|----------|------|
| S | 90-100 | 优秀，可直接使用 |
| A | 75-89 | 良好，小调即可 |
| B | 60-74 | 及格，建议优化 |
| C | 0-59 | 不及格，需重构 |

### 3.3 技术方案

#### 方案：规则 + AI混合评分

```
用户点击"评分" 
  → 第一步：规则引擎快速扫描（<100ms）
    - 检查积木覆盖（角色?任务?约束?格式?）
    - 检查字数（太短<50 / 太长>2000）
    - 检查动词密度
    - 检查安全关键词
  
  → 第二步：AI深度评估（可选，需用户API Key）
    - 调用用户配置的AI模型
    - 按rubric逐维度评分
    - 生成改进建议
    - 推荐可补充的积木
  
  → 输出：评分卡片 + 改进建议 + 积木推荐
```

### 3.4 与主页面集成

在index.html的拼装区域下方添加"评分"面板：
- 用户拼好Prompt后点击"评分"按钮
- 展开评分结果面板
- 显示6维度雷达图 + 总分 + 等级
- 列出改进建议（可点击直接添加推荐积木）
- 支持评分前后对比（保存历史评分）

## 四、实施计划

### Phase 1：规则引擎升级（1-2天）
- 重写`prompt-scorer.html`的评分逻辑
- 6维度评分（替换现有5维度）
- 增加积木覆盖检测（检查拼装的积木是否覆盖角色/任务/约束/格式）

- 在index.html添加评分按钮和面板
- 评分面板可折叠展开
- 点击推荐积木可直接添加到拼装区

### Phase 3：AI深度评估（2-3天）
- 复用已有的API Key配置（testBtn面板里已有）

- 支持多模型对比（同Prompt在ChatGPT/Claude/阶跃上的得分对比）
- 生成优化建议（AI推荐应添加的积木）

### Phase 4：优化迭代（持续）
- 收集用户评分数据
- 校准评分权重
- A/B测试评分Prompt
- 参考 promptfoo 的 evals 方法论做回归测试

## 五、与promptfoo-evals技能的结合

promptfoo提供了系统化的Prompt评估方法论：

1. **评估矩阵**：定义多个测试用例（test cases），每个case有输入和期望输出
2. **断言机制**：assertion检查输出是否满足条件（contains/equals/icontains/json_schema等）
3. **多Provider对比**：同一组测试用例在不同模型上跑，对比结果
4. **评分函数**：自定义评分函数，返回pass/fail

PromptBlocks可以借鉴：
- 预置10-20个"标准Prompt测试用例"（不同场景下的优秀Prompt示例）
- 用户Prompt与标准用例对比，给出相似度和差距分析
- 提供积木覆盖率热力图（哪些维度覆盖了，哪些缺失）
